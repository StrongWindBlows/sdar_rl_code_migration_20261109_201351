# Experiment 2-Joint：联合提交位置与词值 Oracle 执行计划

日期：2026-11-11。状态：2A 已按下述规则实现并完成，376 个矩阵单元去重为 261 个动作。T8 出现一个经复现的联合独有成功状态，T4 未见联合额外覆盖，详见 [结果与人工复核](runs/joint-oracle-20261111/ANALYSIS.md)。运行前版本另存于该运行目录的 PLAN.md；2B 尚未执行。

后续已完成 [50 题扩量](runs/joint50-20261111/ANALYSIS.md)：原 10 加新增 40，协议不变，共 99 个合法源状态和 1368 个唯一动作。新增联合独有 reward 为 T8 1/40、T4 2/40，但新增题等候选数比较没有联合池整体优势。数据用途现为 dev50/eval50/最终400，见 [DATA_USAGE.md](DATA_USAGE.md)。

## 1. 审阅结论

值得做一轮受控验证。此前没有系统比较同一早期状态下的“位置变化 × 词值变化”，已有基础设施也能支持这类动作。首轮检验联合动作是否增加可获得的任务奖励；不预设 GA。

这里的两个因素指当前这一步的动作。Exp 1 固定当前提交集合，并未固定所有未来的提交时刻；Exp 1.6 固定采用当前 top-1 的取词规则，后续具体词值仍可能随上下文变化。

已有证据需要保留以下边界：

- Exp 1 的分歧为零不等于位置正确；错误上下文也可能产生稳定、高置信的错误预测。“在没病的位置动刀”是可能解释，尚非已经证明的原因。
- Exp 1.6 的 T8 7/10、T4 3/10 是事后逐题取最佳动作的上界。T4 的新增 reward 包含一题格式改善，以及一题答案正确但推导仍错误，不能全部解释为推理恢复。
- Exp 1.6 并未证明“只把同一个 token 精确晚交一轮就能救活题目”：T8 的 Reopen 分支没有新增正确；T4 的一个 Reopen1 最终答对，但原 token 在两轮后重新提交，推导仍有错误。撤回还改变了其他位置的条件分布与提交节奏。
- 高置信稳定位置只能作为减少搜索范围的保守约束。按 `p>=0.95` 且历史/当前 top-1 相同统计，20 个既有源状态中，4 个 T8 状态在原提交集合内没有此类位置；两个 T4 状态则各有 7 个，实际可动空间很小。

现有结果依据：[Exp 1](runs/pilot8192-20261110/REPORT.md)、[Exp 1.5](runs/pilot8192-20261110/exp1_5/REPORT.md)、[Exp 1.6](runs/pilot8192-20261110/action_value/REPORT.md)。

## 2. 先执行 2A：单步联合动作

固定复用 `action_value/cases.json` 中 T8/T4 各 10 个源状态，共 20 个；保持原 GPU 分片、TP=1、batch=1、BF16、greedy、checkpoint、prompt 和判分规则。每个分支只在源状态执行一次指定动作，之后返回对应的 T8/T4 策略。

单步动作写作 `a=(S, y_S)`：位置属于 S 表示现在提交，不属于 S 的未提交位置继续保持 MASK。它控制的是“现在交还是以后交”；保持 MASK 不保证该位置恰好在下一轮提交。

### 活跃位置与固定部分

记源状态的全部未提交位置为 M，原动作位置为 S0，q=|S0|，T8/T4 分别为 4/8。

1. **保守锚点 A：** S0 中当前概率至少 0.95、且与上一轮 top-1 相同的位置，固定提交当前值。仅在原 S0 内固定提交，以保持 G0 就是原 Current；不能把块内所有满足阈值的位置额外提前提交。
2. **原集合中的可动位置 R：** 从 S0\A 选最多 3 个。第一位沿用 Exp 1.6 的待延迟位置，其余按“预测变化优先、当前置信度较低、位置索引”确定。记为 r1、r2、r3。
3. **候选换入位置 N：** 最多 2 个；n1 沿用 Exp 1.6 的 Swap1 换入位置，n2 取其余未选位置中当前置信度最高者，概率并列按位置索引。这样保留已有 Swap1/Delay1 作为直接对照。
4. **活跃区 U=R∪N：** 通常 3–5 个位置。S0\R 按原动作固定提交；它包含锚点，也可能包含因搜索名额有限而固定的普通位置，不能全部称为“可靠锚点”。其余背景位置本轮保持 MASK。

未选入 S0 的高置信稳定位置可以作为换入位置，但若提交，其词值固定为当前 top-1。已有提交位置在 2A 中保持原样，不加入撤回操作，避免再增加一个实验因素。

### 用配对矩阵构造候选

采用最多 **5 个位置方案 × 4 个词值方案 = 20 个逻辑组合/状态**。每个联合动作都同时拥有完全对应的单因素对照，不单独给 G3 任意追加候选。

| 位置方案 | 提交集合 |
| --- | --- |
| P0 | 原 S0 |
| P1 | 延迟 r1，提交数 q−1；复用原 Delay1 |
| P2 | 同时延迟 r1、r2，提交数 q−2 |
| P3 | 将 r1 换为 n1，提交数 q；复用原 Swap1 |
| P4 | 同时将 r1、r2 换为 n1、n2，提交数 q |

R 或 N 数量不足时，对应方案记为不可用，不能为了凑候选而解除锚点约束。所有方案至少提交一个位置。

词值方案先定义在同一个 U 上，再投影到各个提交集合；MASK 位置的词值方案本轮不执行：

| 词值方案 | 对 U 的取值规则 |
| --- | --- |
| V0 | 全部当前 top-1 |
| V1 | R 中排序最后的位置改为当前 top-2，其余当前 top-1；该位置较常被位置方案保留 |
| V2 | r1 与第一个允许改变词值的换入位置改为当前 top-2，其余当前 top-1；最多改变两个位置 |
| V3 | 优先选择 U 中相邻、且上一轮 top-1 均不同于当前值的两个位置，成套取上一轮值；多个位置对按索引确定。没有合法相邻对时，退为一个有分歧位置的历史替换；单位置按上述风险排序确定。没有不同历史值则退化为 V0 |

历史只取源状态的上一轮，所有候选均来自源 forward 之前或当次已经获得的信息。相邻历史对只是待检验的候选构造，不视为已证明具有语义兼容性。top-2 与实际 greedy 值相同时按 token ID 去重，不补造候选。

| 分组 | 对应矩阵单元 | 逻辑数量上限 |
| --- | --- | ---: |
| G0：Current | P0 × V0 | 1 |
| G1：Timing-only | P1–P4 × V0 | 4 |
| G2：Allele-only | P0 × V1–V3 | 3 |
| G3：Joint | P1–P4 × V1–V3 | 12 |

按最终 `(S, token values)` 去重，保留矩阵坐标和多重来源标签。若词值变化只涉及未提交位置，该单元实际等于对应的 Timing-only；不把它算作真正联合动作。缺少位置或历史差异造成的退化、候选数和真实联合动作覆盖率均报告，不能用重复动作填满 20 个名额。

## 3. 预算、停止与验收

- 每条路径最多 **512 次实际 forward**，包含恢复重放、prefill、去噪和缓存写入；保持 8192-token 上限与 EOS 规则。无额外模型评分调用。
- 少交的 1–2 个名额统一在源块最后一轮补交，与 Exp 1.6 相同；源块总轮数保持 T，其他完整块使用原静态规则。首轮不混用“下一轮补交”和“最后一轮补交”。
- 候选按同一合法 token 规则处理；MASK 是状态操作，不能作为已提交词值。EOS 保持原合法性，候选包含 EOS 时单独标记，避免把提前终止造成的变化当成有效推理。
- 每个源状态先重跑 Current，比较完整 token、逐轮输入/mask/提交值、终止原因与预算。P1/P3 若对应已有动作，复核其与 Exp 1.6 的一致性。
- 对新词值检查：注入值确实来自指定候选；下一轮输入保留该值；其他已提交值不变；后续回到当前分支自身的模型预测。不能复用旧验收中“所有提交值必须等于当前 top-1”的断言。

最多 20 个状态 × 20 个逻辑组合，即 **不超过 400 个唯一候选续跑**，去重后通常更少。每条 512 是单分支上限，整池总计算量求和报告；额外验收/复现成本也单列。GPU 时间以新入口小规模实测为准。

## 4. 主要结果与归因

主结果为最终任务 reward，格式失败、无答案、forward 截断与明确数学错误单列。所有新增正确案例人工复核答案及主要推导，区分格式修复、答案正确但推导错误、明确的推理改善。

主要判断是：**是否存在 G0、G1、G2 全部失败，而真正的 G3 动作成功的状态。** 同时报告各池 oracle 正确数、覆盖率、纯时机/纯词值是否已能救回，以及候选数相同的比较。

对每个完整的配对矩阵，记录四个值 `Q(P0,V0)`、`Q(Pj,V0)`、`Q(P0,Vk)`、`Q(Pj,Vk)`，并计算：

`I = Q(Pj,Vk) - Q(Pj,V0) - Q(P0,Vk) + Q(P0,V0)`。

正的 I 本身不足以说明实际改善，必须连同四个 reward 解读。若词值变化只在换入位置才被执行，应标记为“新增位置使该词值可被提交”，与在两种位置方案都提交的坐标上观察到的交互分别报告。

G3 仍有更多矩阵单元，不能直接用其 best-of-12 对比 G1 的 best-of-4 来宣称优势。除上述逐组合配对外，匹配 G3 与 G1∪G2 的唯一动作数：两边都包含 Current，再加入相同数量的非 Current 唯一动作，数量取两池可用数的较小值。预先固定 32 个子采样种子 `20261111 + j (j=0..31)`，报告均值与分布；重复子采样只用已经得到的 reward，不增加 GPU 调用，也不挑表现最好的种子。

所有统计按题聚合，T8/T4 分开报告。20 个状态来自同一批 10 题，不是 20 道独立题；400 条分支也不是 400 个独立样本。事后 oracle 上界不作为在线策略成绩。

这些状态实际均在首个完整生成块，未必覆盖关键数学分岔。因此阴性结论限于这批状态、活跃区和候选规则；运行中不按 reward 重新挑时刻或调整阈值。

## 5. 执行顺序与停止条件

1. **CPU prepare：** 核对源状态和代码指纹，生成分区、配对矩阵、合法动作与去重清单。保存规则、seed、候选来源、候选退化与预算清单，再开始 GPU 运行。
2. **接口验收：** 每种设置先用一个固定状态验证 Current、非 top-1 词值注入、少交两个位置后的最后轮补交；通过后处理其余状态。
3. **正式配对：** 使用 GPU 4–7，沿用源状态原 GPU 分片、常驻模型、batch=1。各状态的 Current 验收通过后才运行其余候选，逐动作落盘。
4. **结果复核：** 检查候选完整性、全部预算与恢复验证，输出分组结果和联合独有成功案例。发现非格式性的联合独有成功后，用原配置复现该配对；复现仅用于实现核验，不充当新增统计样本。
5. **阶段判断：** 若只有 G1/G2 改善，说明已试空间中尚无联合额外收益；若 G3 出现独有成功，再考虑两步诊断或扩大其余开发题。无真实联合动作覆盖时先报告设计退化。首轮不访问 80 题评估集，不训练 fitness，不运行 GA。

## 6. 2B：两步次序诊断，后续单独决定

2A 只检验当前提交动作；它不直接证明精确的 `τ=t` 与 `τ=t+1` 次序效应。两步诊断应另行定义三条规则：先 i 后 j、先 j 后 i、同时提交 i/j。

为避免其他位置的时机同时变化，可固定两组公共填充位置，各 q−1 个：前两组每轮提交 q 个；“同时交”组在 t 交 q+1 个、t+1 交 q−1 个。两轮提交的总位置集合和总数相同，整块 T 与整题 512 上限保持不变。

第二轮必须先运行该分支自己的 forward，再确定该轮词值。这样测的是包含重新预测的闭环次序策略；若第二轮词变了，不能说是“词不变、只有时机变化”。如另做固定词值的次序诊断，需要显式标记其冻结假设。这部分不与 2A 混在一个 oracle 池中，首轮文件实现范围仅覆盖 2A。
