日期：2026-11-12。状态：已完成当前本地权重版R1。原14题重跑后7题触发，119条正式恢复、42条直接Dynamic对照及3条确认已完成；未达到扩量门槛。最终解释见[ANALYSIS.md](runs/repetition-recovery-20261112/ANALYSIS.md)。以下保留原计划，实际范围变更以报告为准。

后续：已完成[官方权重复验](runs/repetition-recovery-official-20261112/ANALYSIS.md)，原14状态全部复现，238条正式分支正确恢复为0；同样未达到扩量门槛。官方执行配置为`repetition_recovery_official.json`。

执行补充：用户明确选择继续使用原生模型目录。当前第二个权重分片的SHA256与旧清单不同；运行清单记录新旧哈希，本轮以逐轨迹Current恢复为复用旧状态的必要验收。训练侧的既有变更单列，独立推理入口不依赖这些训练模块。Sampling固定为完整模型词表，与现有greedy词表口径一致。

## 价值判断

值得做一次小规模机制验证。前面的实验主要困难是提前判断何时干预；本实验在已确认循环后介入，可以先直接检验是否仍有恢复空间。

但“采样打断退化”与“回退重生成”本身已有研究。RDD已提出停滞检测、块回退和置信度重mask，其触发条件是仍有mask、但没有token达到置信度阈值。R1应检验的是**置信度很高、持续提交但内容重复**的失败状态；这是与该触发条件的区别，尚不能据此认定有新方法贡献。[RDD原文](https://arxiv.org/html/2602.00150v1)、[神经文本退化与采样研究](https://arxiv.org/abs/1904.09751)。

## 已核对的事实

- 固定使用原开发50题中的14条T8持续精确重复轨迹，全部原reward为0。
- 逐轮只读取已提交的连续生成前缀，首次确认时刻为F39–F221；14/14与旧记录一致。触发后还剩291–473次forward。
- 若回退采用现有的前缀重放实现，再计入重建成本，14题仍有105–450次forward可用于重生成与续写。
- 拟选局部扰动位置中10/14的top-1概率至少0.99。按保存的概率近似计算，temperature=1、每题3次单位置抽样，共42次抽样预计仅0.53次选择非top-1。因此保留T=1对照，同时预先加入T=2组；不根据恢复reward挑温度。
- 在同一个未干预源forward上，用保存概率估算的Dynamic 0.95提交数有8/14大于4。**Dynamic 0.95不等于降低T8的并行度**，G1改称“阈值切换”。这些计数是源分布诊断，不是新Dynamic轨迹结果。
- 同一14题从头运行Dynamic的旧完整轨迹，按512次上限截断重算：0.80为4/14、平均166.1次；0.90为3/14、228.0次；0.95为3/14、237.5次。超预算路径按失败计，成本取512。它们是整体成本参照，不是共享触发状态的干预对照。

逐题触发、回退成本、候选概率和数据来源见[预检记录](runs/r1-preflight-20261112/preflight.json)。预检没有新增GPU forward。

## 固定协议

| 项目 | 设置 |
| --- | --- |
| 模型/引擎 | 原生SDAR-4B-Chat-b32，固定权重，现有LMDeploy，BF16，TP=1，batch=1 |
| 主样本 | 原14条T8循环轨迹，不按恢复结果筛题或替换题目 |
| 触发器 | 精确token周期1–256；至少4份重复且覆盖至少32 tokens；每次提交后，仅扫描当时完整的连续生成前缀 |
| 触发次数 | 每条路径只响应第一次确认；本轮不做反复恢复 |
| 预算 | 每条策略最多512次整题forward、最终保留序列最多8192 new tokens |
| 局部扰动 | 首轮统一为一个位置、一次提交；其余位置按当前T8规则，随后继续T8 greedy |
| Sampling | 完整合法词表的categorical采样，T=1和T=2分开；每温度3个独立种子，不做top-k/top-p截断或拒绝重抽 |
| 种子 | 固定20261112、20261113、20261114；请求内独立RNG，同题各方法使用配对种子，不受任务排序影响 |
| GPU | 预检时4–7较空闲；先GPU6做pilot，通过后优先4–7，正式执行前复核占用 |

temperature=1是模型原分布采样，不称为“升温”。EOS仍遵循原规则；仅采到EOS造成的短输出单列，不当作正确恢复。

## 分组

| 组别 | 触发后的操作 | 路径数/题 |
| --- | --- | ---: |
| G0 Current | 不干预，继续T8 greedy | 1 |
| G1 Threshold Switch | 从下一去噪forward开始切换Dynamic 0.95，直到结束 | 1 |
| G2 Local Sampling | 在首个合格的循环延续位置采样一次，之后T8 greedy | 2温度×3种子 |
| G3 Local Break | 与G2使用相同位置，确定性替换为合法top-2 | 1 |
| G4 Rollback + Local Sampling | 回到统一的块边界；在重生成块内的合格位置采样一次，之后T8 greedy | 2温度×3种子 |
| G5 Rollback + Break | 与G4使用相同回退边界和位置，确定性替换为合法top-2 | 1 |
| GR Rollback + Greedy | 同样回退但不扰动，重生成仍为T8 greedy | 1 |

首轮将G4的扰动范围与G2统一，便于比较回退是否有增量。原提案的“整块sampling”保留为后续强扰动对照；若直接将其与单位置G2比较，会同时改变回退与扰动范围。GR验证回退本身及重放路径，不把KV或mask错误带来的偶然收益当成恢复。

正式计划为14×17=238条路径，包含各独立种子；按每条512上限计算，策略口径最多121,856次forward。短验收与额外复验单列；同配置pilot路径计入正式结果，不重复计数。

## 触发点、位置与回退边界

1. 首次重复确认发生在一轮提交之后，记为F_detect；不能使用本轮尚未提交的预测来确认重复，也不能提前修改已经导致确认的那次动作。
2. 记录当时已看到的重复周期、模板、第二份重复的起点及已确认前缀长度。多个模式同时确认时，按最早起点、较短周期确定唯一模式。
3. G2/G3在触发后最多8次去噪forward内，寻找第一个合格动作：仍masked、属于原T8本轮提交集合、位置在已确认前缀之后、当前top-1等于该重复模板的延续值。多个候选按绝对位置取最早者。选择仅看当前信息，不看未来reward。
4. G4/G5/GR统一回退到`B=32*floor((prompt_length+second_copy_start)/32)`，其中`second_copy_start`是第二份重复起点相对生成序列的索引；B为包含该起点的块开头。删除B及其后的旧token与KV，保留B之前的前缀，将B块重新置为mask。G4/G5在该重生成块中，对起点及其后的首个合格循环延续提交位置扰动。
5. 选位置时仍按原始top-1置信度确定T8提交集合，然后改变选定位置的词值，避免采样后的低概率又改变提交排序。实际干预位置、原/新token、原分布概率、温度分布概率、RNG及下一轮输入全部记录。
6. Sampling允许抽到原top-1，这属于合法无变化试验，必须保留。未找到位置也记为无操作并保留分母，不能换状态重试。预检中14题都找到了对应局部及回退位置，但实际接口仍须核验。

回退边界来自触发时已经观察到的模式，不等于最早数学错误。若错误早已固定在B之前，即使本次不能恢复，也不能推论更深回退必然无效。

## 预算和KV正确性

部署口径按实际经过的阶段记账：

`F_total = F_detect + F_KV_rebuild + F_regenerate_and_continue <= 512`。

- 原始prompt prefill、缓存写入、去噪均计数。丢弃的循环计算不退款，回退重建与重生成也不免费。
- 无回退组的`F_KV_rebuild=0`。按原prompt重放到触发状态的调用，本身对应`F_detect`，不再额外加一次相同前缀成本。
- 回退组若复用现有接口重放B之前的前缀，重放成本额外计入；B块的第一次新forward计入重生成。本轮先用已验证的重放方式，不假设已经实现零forward的KV回退。
- 离线可以共享已建立的触发状态，但每条策略仍分摊完整的`F_detect`。分别报告策略从头执行的总成本与本次新增物理GPU调用量，避免共享工程成本被误写为部署加速。
- 每个分支在最后一个合法forward之前检查预算；长度上限按最终保留token计算，丢弃或重放token不重复计入输出长度。
- 不把稀疏已提交token压紧成prompt，不复用被撤回块的活动KV。以后若优化KV截断/快照，需重新通过一致性验收和计时。

主比较用512预算内的G0，不用旧T8的两千多次forward放大节省比例。旧8192-token完整循环只作背景；从头Dynamic 0.80/0.90/0.95同时作为部署成本参照。

## 指标

| 指标 | 口径 |
| --- | --- |
| Escape | 正常EOS，干预后的保留后缀未再次满足原持续重复规则；原先已保留前缀中的旧重复不直接判失败。立即EOS、只删掉重复、换成另一种循环分别列出 |
| 原reward | 沿用原结束、答案提取与数学等价规则，便于与旧实验比较 |
| 有效正确恢复 | 原reward=1，且复核后续核心解题链条基本有效；“答案碰巧对/格式修复/推导错误”单列 |
| Total Forward | 上述全阶段成本；并报告中位数、均值、预算耗尽及相对G0、从头Dynamic的差值 |
| TPF_denoise | 最终保留生成token数 / 所有已付出的去噪forward，包括被回退和重放的去噪调用 |
| TPF_total | 最终保留生成token数 / F_total，包含prefill和缓存成本 |
| Overhead | 分列KV重建、重生成旧位置、越过旧生成边界后的续写，以及检测/采样CPU与GPU耗时；没有额外模型评分forward |

后缀检查从无回退组的触发前缀末端、回退组的B开始；另记录最后一次实际扰动之后原周期是否继续、新周期是否形成。退出循环不等于恢复数学推理。对成功与可疑失败进行文本复核，保留原reward，复核不作为选择干预状态的依据。

随机组报告逐题0/3–3/3成功、题均成功率、各固定种子的总体成绩和波动，绝不报告best-of-3为单次部署成绩。置信区间按题聚合，不能把42条种子路径当成42道独立题。

## 分阶段执行

1. **冻结与CPU校验。** 固定14题、触发器、边界、位置规则、温度和种子；核对反事实账本、遮罩、词表规则、无操作计数及采样分布。预检数据只作状态可用性说明。
2. **3题pilot。** 按干预前特征选：`intermediate_algebra/1126`（最早周期1）、`prealgebra/1251`（最早周期>32）、`precalculus/1133`（最晚确认）。检验G0逐轨迹复现；GR回退后复现原逻辑路径；G1真实提交数；G2/G4真实categorical采样；G3/G5确实注入top-2；预算和KV不串分支。只按正确性决定是否扩到14题，不按这3题是否被救回调整规则。
3. **全部14题。** 同题各组尽量同卡，方法顺序随机，种子固定；完成238条计划路径，记录真实无变化率、预算耗尽与复发。每个检测事件只恢复一次。
4. **复核与报告。** 分开报告逃逸、答案、有效推理、成本；确定性成功按相同条件复跑，随机成功用预留新种子检查，并明确额外试验成本与选择过程。
5. **按证据扩展。** 若至少两个独立题（含新增40题中的题目）有有效正确恢复，才视为机制正面信号。优先判断普通局部采样是否已经足够；更复杂的回退或定向扰动还须展示相对普通局部采样的增量。若选定方法相对G1及从头Dynamic显示有意义的质量/成本折中，再冻结一种恢复规则，在原50道完整开发题上检查误触发和净收益，然后测试Dynamic 0.75/0.80搭配。恢复两题本身不保证优于从头Dynamic，仍需完整策略比较。400题保留到最终方法冻结。

若仅退出循环或只能提前EOS，结论是格式/终止改善，不称为推理恢复；若重放成本使方法被直接Dynamic支配，先记录机制与工程成本的区别，不直接进入算法扩量。

## 实现范围

计划新增三个文件，复用现有模块：

- `ga/repetition_recovery.py`：触发、位置选择、局部采样/词值覆盖、回退任务、成本账本及报告入口；运行时适配集中在一个Backend子类。

- `ga/test_repetition_recovery.py`：因果触发、同位置对照、RNG隔离、回退/长度计数和预算校验。

读取并复用`engine.py`、`early.py`、`protocol.py`和`degeneration.py`；不需要修改训练入口或LMDeploy源码。现有Backend固定`do_sample=False, top_k=1`，因此必须在局部hook中显式实现采样，不能只修改temperature参数。

输出放在独立的`ga/runs/repetition-recovery-日期/`：配置/代码指纹、触发快照、逐路径结果、轨迹、验收与成本审计、数学复核及`REPORT.md`。执行后更新`ga/README.md`、`ga/EXPERIMENT_SUMMARY.md`；当前仅增加本计划和只读预检记录。
