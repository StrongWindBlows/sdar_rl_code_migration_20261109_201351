## b16 到 b32 的对应调整

静态完整块每轮提交数为 `B / T`。为了保留四位置动作，原 B16-T4 的主要机制工作点对应 B32-T8。原来的 T4 预算保留为更激进的压力对照。

| 设置 | 块内去噪轮数 | 完整块每轮提交数 | 用途 |
| --- | ---: | ---: | --- |
| B32-T32 | 32 | 1 | 高计算参考 |
| B32-T16 | 16 | 2 | 中间工作点 |
| B32-T8 | 8 | 4 | 四位置重组的主要源策略 |
| B32-T4 | 4 | 8 | 原四轮预算的压力对照 |
| B32-Dynamic | 自适应 | 阈值通过者，至少 1 个 | 实际自适应基线 |

静态使用 `low_confidence_static`，按当前候选置信度选择 masked 位置，确定性地提交当前 top-1。每轮是固定提交数，尾部不足时取剩余数；不是额外叠加阈值规则。首个混合 prompt 块可能不足 32 个待生成位置，单独记账。

Dynamic 使用本地引擎普通 `low_confidence_dynamic`，默认建议阈值 0.9，并显式设置 block length 32。它的保底数为 1，`denoising_steps` 不控制其最大轮数；完整块最坏需要 32 次提交轮。暂不采用本地 enhanced 变体。

## Experiment 0：质量、计算量与自然轨迹

先在开发集的 10 题 pilot 上运行上表五种配置，检查执行、耗时、T8/T4 候选分歧及质量差距；有必要时扩展到全部 20 题开发集。冻结配置后才在 80 题评估集执行预定比较。报告正确率、逐题配对差值、两种不一致方向的题数、题级配对 bootstrap 区间 / McNemar 检验、截断率、生成长度、forward 次数和耗时。按题聚合，不把同一题的块或状态当作独立样本。

同时检查 T8 相对 T16/T32、T4 相对 T8/T16/T32 的差距。平均正确率相近时仍检查是否存在明显题目互换。100 题用于机制筛查；“未发现显著差异”不足以断言“几乎无质量损失”。

每轮保存：

- question / request / block / round / forward ID，绝对 token 位置及预算计数。
- 提交前 input token IDs、masked / unmasked / cached 标记；提交后变化、提交位置集合和 token 值。
- 所有尚未提交位置的当前 top-5 IDs / 概率、top-1、熵、top-1 与 top-2 的 margin。
- 历史提案来源及其生成时概率；同时查询历史 token 在当前分布下的概率，避免直接比较不同条件下的置信度。
- 在当前仍 masked 的相同位置上计算历史 / 当前 top-1 分歧；完整 mask 与提交前状态必须先 clone，避免原地操作污染记录。
- 在实际准备提交的集合 S 内单独记录历史 / 当前 top-1 不同的位置数 `d_S`，不能用整个 masked 块的分歧率替代。
- EOS、截断、异常和必要的 RNG / sampler metadata。

分歧率仅衡量候选多样性。真正的新组合需要至少两个位置的父代取值不同；分歧本身不证明任务收益。

对有上一轮历史提案的合法第 2/3 轮状态，先按基线当前置信度确定 S，再统计：

`d_S(s) = sum(历史 top-1[i] != 当前 top-1[i] for i in S)`。

- T8 的 `|S|=4`：报告 `d_S=0,1,2,3,4` 的数量/占比、`P(d_S<2)` 和 `P(d_S>=2)`，按干预轮次和题目汇总。缺少历史或不合法的状态单列，不当作零分歧。
- 对当前/上一轮两来源池，去重后的候选数为 `2^d_S`；排除纯父代的新混合动作数为 `max(2^d_S-2, 0)`。`d_S=0` 时两父代相同，`d_S=1` 时只有两个纯父代，均没有新的混合动作。
- T4 同时报告完整八位置集合 S 的分歧数，以及实际允许重组的四坐标 U 内的分歧数；四坐标诊断是否有新混合动作以 U 内分歧为准。

开发集上的执行分流：若多数合法 T8 状态 `d_S<2`（占比超过 50%），优先检查 T4 的可变坐标分歧和质量差距，必要时在开发集增加高分歧位置诊断。不能因 T8 缺少可交叉状态而直接判定重组机制无效。

高分歧位置诊断单独标记：位置仅根据干预前预测选定，每个源状态先锁定诊断集合 `S_diag`，随后所有动作共用它，并以相同 `S_diag` 上的 Current 为控制。其结果只解释这些位置上的内容重组；不能把它与原始置信度位置基线的总差异全部归因于 token 重组，也不能混入自然 S 的主要结果。诊断位置规则也须在开发集确定后冻结。

forward 记账包含 prompt prefill、去噪、完整块写入 KV、候选评分和重放开销。`step_map` 只统计提交事件，不等于真实 forward 次数。本地状态机在全块已提交后还有 cached 状态转换，因此 T4/T8 的端到端速度比不能直接按 2 倍计算。

吞吐测量使用关闭详细落盘的运行；轨迹记录开销另测，保留相同 batch、长度上限和 warmup 口径。

## Experiment 1：固定位置的配对重组 oracle

默认源策略为 B32-T8；是否采用已有的 T4 四坐标方案由开发集的分歧及质量结果确定，进入评估前冻结。只使用自然到达的完整生成块，第 2 或 3 次提交前（当前 forward 已完成、当前动作尚未执行）。排除 prompt 混合块和 EOS 后无效位置。每题按固定种子从合法块中选一个，不按最终 reward 筛选；无合适状态的题目记录为缺失，不偷偷替换题目。

正式生成任何分支 oracle 结果前，必须通过“保存状态 → 恢复状态 → 执行原来的 Current 动作 → 继续生成”的恢复验收：

1. 保存不中断 greedy 基线的完整 token IDs 和逐轮轨迹；在同一轨迹的第 2/3 轮提交前保存快照。
2. 在隔离的请求状态中恢复快照，核对当前块 token/mask、绝对位置、轮次、剩余预算、停止条件及一致的 KV 状态；使用原始 Current 的提交位置与 token 值，并按原策略继续。
3. 与不中断基线逐项比较：Current 动作、后续逐轮 mask/提交集合/提交值、最终完整 token IDs（含 EOS）、终止原因、后续去噪/缓存 forward 计数与预算扣减必须一致。重建源状态产生的 prefill/replay 按原有规则单列。只比较最终文字或 reward 相同不足以通过。
4. 在固定模型、精度、代码及 batch/执行配置下重复恢复，检查分支运行顺序不会污染状态；更换并发或 batch 配置后，在新配置下重新验收。任一差异都先定位首个分歧事件，修复后再启动正式候选分支实验。

先用开发集 pilot 验证上述恢复流程；验收通过后才运行首批 10 个源状态的候选动作。若部分 pilot 题没有合法状态，报告实际覆盖，不从 80 题评估集补足。

先按基线当前置信度确定 `S`，`|S|=4`，随后锁定 S；所有取值动作从完全相同的源状态出发。

| 动作或候选池 | 定义 |
| --- | --- |
| Current | S 上全部取当前 top-1 |
| Historical | S 上全部取上一轮历史 top-1 |
| Current-only | S 上每个位置取当前 top-1 或 top-2，最多 16 个组合 |
| Cross-round | S 上每个位置取当前或历史 top-1，最多 16 个组合；纯父代单列 |

按最终 `(S, token values)` 去重并保留多重来源标签。两池共享 Current，合并最多 31 个实际动作。所有历史取值都来自干预前已获得的信息。

完整枚举给出各池上界，同时做相同唯一候选数的预算配对比较：对较大池按预注册种子取同等数量的候选，保留 Current 控制，并报告去重后的数量、重复覆盖和父代结果。候选数量不等时不把 best-of-N 差异直接当作重组收益。

主要证据包括：

- 新混合动作是否优于两个纯父代；greedy 的二元 reward 下，尤其看两个父代都失败而混合成功的状态。
- 相同候选预算下，Cross-round 是否优于 Current-only。
- 历史 token 是否属于当前 top-2 支撑集；若完整 cross pool 已包含在 current-only pool 内，不能声称历史扩大了候选内容空间。有限搜索下的选择效率收益单独解释。
- 含新混合动作的状态覆盖率、退化池占比，以及在全部源状态分布上的效果。可再报告高分歧子集，但不能只展示它。

每个分支只干预一次，随后都回到同一个 T8 策略。共同使用同一个剩余 forward 上限、总生成长度上限和停止规则，EOS 可提前结束，预算耗尽按统一规则判分。源状态的创建成本共用；为恢复源状态而发生的 prefill/replay 单独计工程耗时，不偷占或增加任一动作的未来决策预算。

greedy 续跑的 Q 是固定策略、固定预算下的确定性结果，一次续跑即可；重复相同 greedy 路径不能估计随机期望。首批 10 个开发状态最多约 310 条续跑；有正面信号后可扩展至 20 题开发集，最多约 620 条。配置冻结后的 80 题评估集最多约 2480 条，合计 100 个状态最多约 3100 条。先去重、分批并行并测量实际 token/forward 消耗。

如果开发集显示 T8 的可改进空间弱、而 T4 损失明显，或多数 T8 状态缺少至少两个分歧位置而 T4 有可用分歧：优先在开发集尝试 B32-T4 的自然状态，锁定完整提交集合 `|S|=8`。先只允许其中预先选定的 4 个坐标 U 重组，其余 4 个固定 Current，保留 16 组合的成本。这只能称为四坐标干预结果；完整八坐标两来源枚举为 256 个组合/池。U 的选择必须仅依赖干预前信息并预先固定，不能按反事实 reward 选择。

主实验在固定取值实验完成后才开放 S；前述高分歧位置实验是单列的机制诊断。局部 oracle 收益还需通过整条生成中的重复干预验证，不能直接等同于可部署策略的端到端正确率提升。

## Experiment 1.5：早期提交失败分析

先用已有轨迹分析 T8 失败题，按题目与数学依据定位首次可确认的错误片段，以及持续重复起点。分别记录可疑 token 的提交事件、错误片段全部提交的时刻和原 Experiment 1 的干预时刻；错误 token 的人工定位不等于已经找到最早因果错误。语言崩坏与可确认的数学错误分开标记。

保留问题发生前完整的已提交 token/含洞状态，检查可疑位置在提交前的历史提案，并统计旧分支的完整输出、源块之后的 suffix、结束原因及实际答案。缺失答案与数值答案 0 分开；重复起点回溯时间与达到检测阈值的时间分开。

已提交位置的原始 logits 在实测中主要对齐右邻 token，不能直接作为自身不稳定性指标；缓存后的旧位置也没有更远上下文下的重新预测。只有实际重新 mask 后的条件分布，才用于局部重新预测诊断。

首批小验证限原四道失败题：每题保留不撤回控制，以及撤回 1/2 个预先指定位置的两条分支，共 12 条。先复现原 Current 提交，再将活跃块中的指定位置改回 mask，交由 T8 自行生成，不指定正确 token。所有分支共用剩余 T8 forward 上界加 1 的预算和 8192 总长度上限；恢复开销单列。控制必须复现原轨迹，重开后下一轮输入/mask 与其他已提交值必须核对。

错误消失、重复消失、正常结束和最终任务正确分别记录。人工按失败轨迹定位属于回溯诊断；若有恢复案例，后续还需验证不依赖答案的在线选点规则、同预算的延迟提交/随机位置重开对照，以及对原本正确题的损害。这不替代固定位置跨候选内容重组实验。

## Experiment 1.6：相同 forward 预算下的早期动作价值

2026-11-10 按新增请求执行的小规模尝试已完成，独立于原跨候选重组路线。原 10 题开发集同时覆盖 T8/T4 和原本正确题；不增加题目，不预设使用 GA。下述规则在 GPU 运行前写入清单，实测结果见 [Experiment 1.6 报告](../../ga/runs/pilot8192-20261110/action_value/REPORT.md)。

每题每种设置至多选择一个源状态：完整生成块起点位于前 256 个生成位置内，块内第 2 至 T−1 轮，首次出现待提交位置的当前 top-1 置信度低于 0.9 或相对上一轮发生变化。选择只读取到当前 forward 的信息，不按正确性或后续重复筛选。找不到状态时单列覆盖，不替换题目。

在同一源状态比较五种动作；所有新提交值均来自当前 top-1：

| 动作 | 操作 |
| --- | --- |
| Current | 原提交集合与取值 |
| Swap1 | 将一个风险最高的待提交位置换为未选 masked 位置中风险最低的一个，提交数不变 |
| Delay1 | 本轮少提交一个风险最高的位置；后续轮次允许再选择它 |
| Reopen1 / Reopen2 | 执行 Current 后，撤回当前活跃块内此前已提交的 1 / 2 个风险最高位置，等待模型重新预测 |

风险按“提交前 top-1 刚变化优先、置信度较低其次、位置索引”排序。撤回位置使用该位置原提交时的记录，禁止把已可见位置的后续原始 logits 当成自身质量评分。该规则仅是无需额外模型调用的启发式，不声称已经估计出动作价值。

所有分支使用 **整题 512 次实际 forward 上限**，包含 prefill、缓存写入及恢复重放，EOS 可提前结束；不额外增加修订预算。干预块保持原 T8/T4 轮数，延迟或撤回造成的未提交位置在最后一轮一并提交，之后回到原策略；总长度上限仍为 8192。512 上限在原轨迹中保留了所有原本正确的回答，原基线也按该上限比较。

共最多 20 个源状态 × 5 个动作 = 100 条续跑。每个状态先通过 Current 与不中断基线在相同预算下的逐 token、逐轮恢复比较，再运行其余动作。检查实际注入、下一轮输入、已提交值、块内轮数及整题 forward。报告各方法的正确数、新增正确/丢失、结束原因、长度和实际计算量；逐题选最佳动作只作为付出全部试验成本后的诊断上界，不作为策略成绩。配置、规则、源码和源数据指纹在运行前写入 `ga/runs/pilot8192-20261110/action_value/manifest.json`。

## Experiment 2：联合提交位置与词值 Oracle

2026-11-11 按新增请求实现并完成，规则见 [联合 Oracle 执行计划](../../ga/JOINT_ORACLE_PLAN.md)。固定复用 Experiment 1.6 的 T8/T4 各 10 个早期状态，以最多 5 个提交集合 × 4 个词值方案构造配对矩阵；20 个状态的 376 个逻辑单元去重为 261 个动作，其中真正联合动作 122 个，全部状态均有覆盖。

保留原 Current、Delay1 和 Swap1。只在 3–5 个活跃位置内改变本轮提交集合或词值，保护稳定高置信位置，并固定原动作中的其余位置。各分支最多 512 次实际整题 forward，包含恢复、prefill 与缓存写入；少交名额统一在源块原定最后一轮补齐，之后返回原 T8/T4。

主要检验是否存在 G0/G1/G2 全部失败而真正 G3 成功的状态；同时报告四格配对交互和等唯一候选数比较。格式改善、答案正确但推导错误、明确数学改善分别复核。原廉价评分器作为以下后续条件阶段保留；本实验不依赖原跨轮内容重组出现收益，不预设 GA。

实测 T8 的 Current/纯位置/纯词值/联合 oracle 分别为 6/7/7/8 题，`1014` 出现联合独有成功；T4 为 1/2/3/3，没有联合额外覆盖。各池保留 Current，属于事后上界。两个成功联合动作及其对照共 7 个唯一动作逐轨迹复现；新增 reward 已人工复核，结果见 [Experiment 2 报告](../../ga/runs/joint-oracle-20261111/ANALYSIS.md)。23 个 CPU 校验、20 个 Current 和旧 Delay1/Swap1 对照及 261 条路径独立审计通过。未启动两步次序、评分器或 GA。

随后按冻结规则完成 [50 题扩量](../../ga/runs/joint50-20261111/ANALYSIS.md)：全 50 题 T8 Current/单因素并集/全池为 22/33/35，T4 为 7/16/18。新增 40 题为 T8 16/26/27、T4 6/13/15；新增联合独有案例共三个，12 条成功/单因素对照逐轨迹复现。新 T8 几何案例主要推导正确，T4 一例推导错误、一例关键直接计算正确但解释损坏；等候选数比较未显示新增题上的联合池整体优势。共 99 个合法状态、1368 个唯一动作，其中复用旧 261 条、新增 1107 条；100 条基线及全部新/复用路径审计通过，25 个 CPU 校验通过。

## 后续条件阶段：廉价评分器（原 Experiment 2）

只有开发集上已明确的候选池观察到任务奖励收益才启动。原方案针对 Experiment 1 跨轮重组池；新路线可针对 Experiment 2 的联合池，但须单独定义候选与标签，不能把两种池的结果混用。保持同一候选池，以当前概率、历史信用、稳定性、无需额外 forward 的局部启发式为起点。需要反事实模型调用的交互评分器必须单列其 forward 和时间成本。

主指标是候选池内 regret、相对 Current 的实际奖励变化和正确候选选择率。greedy 二元结果存在大量并列，不能强行解释精细排名。

若需估计随机续跑价值，在一小批有信息量的状态上先用固定温度 1、完整采样分布，并为所有动作配对相同的续跑随机流。用一组种子估计并选择候选，用另一组独立种子重估所选动作和参照动作。可先用 4+4 次做筛查，信号不确定再增加；4 次不保证估计精度。

有限样本选出的最佳动作只是经验参照，需要报告不确定性；不能用同一批带噪样本先取 max、再报无偏 regret。评分器参数仅在 20 题开发集调节，80 题评估集按题隔离；同一题的多个状态不得跨集合。

## Experiment 3：是否需要搜索与 GA

四个二元位置仅 16 种组合，初版直接枚举并用廉价评分器打分即可。只有扩大到更多位置、多历史来源或位置/取值联合选择、无法穷举时，才比较搜索策略。

固定可行动作空间、候选生成信息、fitness 和不同候选的评分预算；预算应小于可行空间大小。比较 greedy、局部搜索、随机搜索和结构化 crossover。若固定的是显式候选列表，算法只能选择访问该列表中的哪些候选；若允许产生新 crossover 子代，则统一的是可行空间和预算，不能再宣称访问了相同候选池。

当所有方法已评完同一个池且使用相同 fitness 时，它们都会选同一个最大值，这种设置无法检验搜索策略优势。

分叉需要保留完整已完成前缀、当前块含洞 token/mask、位置、轮次/预算、停止条件、采样元数据以及与状态一致的 KV。完整已完成前缀可重建或安全共享；活动块的 KV 不能随意跨分支复用，也不能把稀疏已提交 token 压紧后当普通追加 prompt。首版可重建前缀并注入当前块状态，正确后再优化安全共享与分叉批处理。

上线正式 benchmark 前的必要小检查：

1. B32 静态提交数分别为 1/2/4/8，已提交 token 不变，正常处理 prompt 尾块、EOS 和长度上限。
2. 开启轨迹记录前后的 greedy 输出与提交路径相同。

2026-11-10 已完成 CPU 校验、短 GPU 验收及真实 pilot 的恢复检查。分叉通过原 prompt 上的提交轨迹重放重建 KV，恢复成本与未来决策预算分开；直接批量 prefill 完整前缀曾产生 BF16 路径差异，因此未采用。实际范围、结果和数值对照限制见上述首轮报告。
